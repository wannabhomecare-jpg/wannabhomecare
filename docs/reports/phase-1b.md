## 한 것

1. `normalizeKakao`(`src/lib/contact.ts`)
   - `http://`·`https://`, 호스트 `pf.kakao.com`(대소문자 무관), 경로 `/_<영문·숫자>` 와 뒤의 `/chat`·`/friend`·`/` 를 받는다. 쿼리·`#` 는 버린다.
   - 돌려주는 값: `{ id, home: https://pf.kakao.com/_<ID>, url: https://pf.kakao.com/_<ID>/chat }`.
   - 그 밖(오픈채팅 주소, `_` 없는 경로, `javascript:`, 빈 값, `#`, 비슷한 다른 호스트, 다른 하위 경로)은 null.
2. 카카오 버튼 5곳(첫 화면 카드, 견적 옆, 견적 완료 화면, 휴대폰 하단, PC 오른쪽)이 모두 `BUSINESS.contact.kakao.url` 을 쓰고 새 창으로 연다. 주소를 직접 적은 곳은 없다(테스트로 확인).
3. 미리보기 띠: 카카오 연결 여부와 '사진 준비 중' 자리(첫 화면 6장 + 서비스 6칸, DB 값 기준)에 따라 네 가지 문구 중 하나가 나온다.
4. 구조화 데이터 `sameAs`: 채널이 있으면 인스타그램 뒤에 채널 홈 주소를 넣는다.
5. `check:launch`: 같은 정리 규칙으로 판단한다. 실패 문구를 "비어 있거나 pf.kakao.com/_<ID> 형식이 아닙니다"로 고쳤다.
6. `.env.example` 설명을 고쳤다(값 없음).
7. 문서: ROADMAP 에 1b 줄, `docs/launch-checklist.md` 에 사람이 확인할 4줄.

## 가정·바꾼 점

- **읽어 주는 이름(aria-label)**: 프롬프트는 "카카오톡 1:1 상담 (새 창)"이었다. 그대로 넣었더니 자동 접근성 검사(axe)가 `label-content-name-mismatch`(WCAG 2.5.3, 보이는 글자가 이름 안에 없음)로 실패했다. 그래서 보이는 글자로 시작하고 뒤에 붙였다. 예: "카카오톡으로 빠른 상담 · 카카오톡 1:1 상담 (새 창)", "카톡상담 · 카카오톡 1:1 상담 (새 창)". 연결 전에는 "(새 창)" 대신 "(아직 연결 전입니다)"가 붙는다.
- 미리보기 띠는 레이아웃에서 DB 의 첫 화면 값과 서비스 값을 읽어 판단한다. DB 를 못 읽으면 기본값으로 본다.
- 테스트 파일에는 예시 ID `_AbC123` 만 쓴다. 오픈채팅 예시는 저장소 검사 금지어에 걸리지 않게 문자열을 나눠 썼다.
